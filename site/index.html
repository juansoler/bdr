01 — Arquitectura

Tres piezas. Ninguna caja negra.

Componentes open source probados, orquestados por un plano de control propio. Código auditable, estándares abiertos y ningún componente propietario en la ruta de tus datos.

01

Plano de control

bdr-control es un único binario Go con panel web embebido, API REST, programador de planes, RBAC con TOTP y auditoría encadenada. Sin Node en runtime.

  • Panel Next.js exportado y embebido con go:embed
  • PostgreSQL opcional o state.json cifrado
  • API mTLS en :8443, panel en :8080
02

Repositorio

Kopia para archivos: incremental, deduplicación por contenido, compresión zstd y cifrado en cliente. Proxmox Backup Server para VMs. En NAS, disco local o S3.

  • La clave maestra nunca viaja a los agentes
  • Kopia Repository Server opcional
  • Retención GFS y ventanas de horario
03

Agentes

bdr-agent en cada equipo: instantáneas consistentes con VSS, LVM, Btrfs o ZFS, inventario de discos y TPM, y auto-actualización verificada por SHA-256.

  • Enrolamiento con token de un solo uso
  • mTLS con identidad propia por equipo
  • Servicio nativo: systemd, SCM o launchd
Tu servidor bdr-control panel · API · scheduler
Repositorio Kopia · PBS dedup · zstd · cifrado
Equipos bdr-agent Linux · Windows · macOS

02 — Capacidades

Todo lo que hace falta para dormir tranquilo.

Del fichero suelto a la base de datos en producción, con el mismo plano de control y el mismo catálogo de restore points.

◧

Archivos

Kopia real: incremental, dedup por contenido, compresión zstd y cifrado en cliente.

▤

SQL Server

FULL, DIFF, LOG y COPY_ONLY con COMPRESSION y CHECKSUM; VERIFYONLY, DBCC CHECKDB y PITR con STOPAT.

◫

PostgreSQL

pg_dump en formato custom, verificado con pg_restore --list, restauración con createdb o --clean.

▣

VMs de Proxmox

Proxmox Backup Server orquestado por API: backup, verificación y restauración por VM.

◉

Acceso por pantalla

Consola remota en el navegador con tiles JPEG, estilo MeshCentral, y helper nativo en Windows.

⏱

Programación

Planes con cron, ventanas de horario, retención GFS y grupos con jerarquía.

◈

Verificación

Niveles 1–2 de recuperabilidad, explorador de archivos y restauración desde el panel.

✦

Alertas

Deduplicación, webhook firmado y email con reintentos. Lo que falla, se sabe.

↑

Actualizaciones firmadas

Canal de releases con Ed25519: el servidor notifica y tú decides. Nada se instala solo.

En el roadmap: imágenes completas con VSS/LVM/Btrfs/ZFS, restauración P2V a Proxmox, ISO de rescate, réplica 3-2-1 a S3 con Object Lock y alta disponibilidad.

03 — Motores de datos

Bases de datos tratadas como lo que son.

El motor corre dentro del agente, en el host de la base de datos. El control orquesta: backup nativo → transferencia al destino → catálogo con metadatos para restaurar.

SQL Server

Windows
  • Autodetección de instancias y del BackupDirectory
  • Cadenas FULL → DIFF → LOG calculadas por continuidad de LSN
  • PITR con punto en el tiempo y destino en otra instancia
  • Cifrado nativo con custodia de certificados .cer/.pvk
  • Runbook de master con bdr-sql runbook-master
API
POST /api/v1/admin/sql/{backup,restore,verify,checkdb}
POST /api/v1/admin/sql/restore-chain
GET  /api/v1/admin/sql/restore-points

PostgreSQL

Linux · Windows
  • Autodetección de puertos y clústeres
  • pg_dump --format=custom comprimido y verificado en cada job
  • Restauración en motor limpio o con --clean --if-exists
  • Credenciales solo en el entorno del agente, nunca por la API
  • Inventario de bases y catálogo de restore points
API
POST /api/v1/admin/pg/{dump,restore,verify,inventory}
GET  /api/v1/admin/pg/restore-points
POST /api/v1/admin/pg/discover

04 — Seguridad

Las copias son el último recurso. Protégelas.

Modelo de amenazas documentado, controles por defecto y ninguna clave maestra en los equipos protegidos.

mTLS obligatorio

Cada agente se identifica con su propio certificado. Sin identidad válida no hay API.

RBAC + TOTP

Sesiones con segundo factor, roles separados y auditoría encadenada de cada acción.

AES-256-GCM

Secretos y estado en reposo cifrados; el repositorio usa cifrado en cliente.

Canal firmado

El catálogo de releases se verifica con Ed25519 embebido en el binario.

Custodia de claves

Certificados de cifrado SQL sellados en el control, con alerta si desaparecen.

Sin telemetría

Tu servidor no llama a casa. Solo consulta el canal de versiones que tú decidas.

05 — Instalación

De cero a primera copia verificada.

El instalador genera los secretos, registra el servicio e inicializa el repositorio Kopia una sola vez. Revisa siempre el script antes de ejecutarlo.

Linux / macOS

servidor
bash 
curl -fsSL https://github.com/juansoler/bdr/releases/latest/download/install-linux.sh -o install.sh
less install.sh
sudo bash install.sh

Sin sudo (Debian minimal, Proxmox): ejecuta el script directamente como root.

Windows

servidor
powershell 
irm https://github.com/juansoler/bdr/releases/latest/download/install-windows.ps1 -OutFile install-windows.ps1
notepad install-windows.ps1
.\install-windows.ps1

PowerShell como administrador. El servicio se registra con recuperación automática.

Docker Compose

stack completo
bash 
git clone https://github.com/juansoler/bdr.git && cd bdr/deploy
docker compose -f docker-compose.prod.yml run --rm kopia-init
docker compose -f docker-compose.prod.yml up -d

Incluye Caddy con Let's Encrypt. Define antes las variables de .env.

  1. 1

    Entra en el panel

    Abre http://<servidor>:8080 e introduce el token de /etc/bdr/bdr.env.

  2. 2

    Añade tu primer equipo

    En Equipos → Añadir equipo se genera un instalador con token de un solo uso para Linux, Windows o macOS.

  3. 3

    Lanza y verifica

    Ejecuta un backup, abre el restore point y comprueba que figura como recuperable. Ese es el único estado que importa.
